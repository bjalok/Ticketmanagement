Build a React 19 + Vite + Tailwind CSS 4 ticket management system that simulates an 
AI-powered support ticket triage and resolution pipeline. The UI is a 3-panel layout 
with a ticket queue, an agent pipeline view with live telemetry, and a details panel. 
All processing is simulated — no real API calls.

WORKFLOW & STATE MACHINE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
State variables needed (all useState):
  selectedTicketId       — which ticket is active
  thinkingTicketId       — which ticket is animating the "thinking" state (3s)
  routingTicketId        — which ticket is in routing/S4 animation
  agentActiveTab         — 'Overview' | 'Details'
  searchQuery            — left panel search filter

Per-ticket animation state groups (keyed by ticket scenario):
  [prefix]PreSteps[]     — pre-check steps array, builds up
  [prefix]PreDone        — boolean, all pre-checks done
  [prefix]ContextSteps[] — CTI detection steps array
  [prefix]ContextDone    — boolean
  [prefix]DupSteps[]     — duplicate detection steps array
  [prefix]DupDone        — boolean
  s4Steps[]              — routing steps for S4 execution card
  s4Done                 — boolean

CLICK HANDLER on ticket card:
  1. Set selectedTicketId, reset tab to Overview
  2. If ticket already fully processed → just show stored results
  3. Else: setThinkingTicketId(id), after 3000ms:
       clearThinkingTicketId, call processAIEnrichment()

processAIEnrichment(ticketId, description):
  1. Word-count check: if description < 10 words → inject enrichment comment 
     (bot message with missingFields array) into ticket comments
  2. Match scenario with keyword search against SCENARIO_LIBRARY
  3. Match past resolution with keyword search against PAST_RESOLUTIONS
  4. Start routing animation: setRoutingTicketId(id)
  5. Build S4_STEPS execution sequence (6 steps, each 2000ms apart)
  6. Simultaneously animate CTI detection steps (7 steps, 700ms apart)
  7. Animate duplicate check steps (7 steps, 700ms apart)
  8. After all steps done: inject routing comment into ticket.comments
     (contains scenario, pastResolution, escalation, isDuplicateOf, kbArticlesOnly)
  9. Clear routingTicketId

ANIMATION PATTERN (used everywhere):
  const timers = [];
  STEPS.forEach((step, i) => {
    timers.push(setTimeout(
      () => setState(prev => [...prev, step]),
      BASE_DELAY + i * INTERVAL
    ));
  });
  timers.push(setTimeout(() => setDone(true), 
    BASE_DELAY + STEPS.length * INTERVAL));
  return () => timers.forEach(clearTimeout);

Timing constants:
  SUB_FIRST_DELAY = 380ms   (first sub-step after parent appears)
  SUB_INTERVAL    = 560ms   (between sub-steps)
  STEP_NO_SUB_DONE = 850ms  (step with no sub-steps completes after)
  NEXT_GAP        = 180ms   (gap between parent steps)
  S4 routing total ≈ 7500ms + (6 steps × 2000ms) + 1200ms cleanup = ~20.7s

matchScenario(description):
  lowercase description, check which SCENARIO_LIBRARY entry has 
  the most keyword hits → return that entry or null

matchPastResolution(description):
  same approach against PAST_RESOLUTIONS keywords → 
  return best match or null

isDuplicate(description, existingTickets):
  simple substring/keyword overlap against other tickets → 
  return matched ticket ID or null

ADDITIONAL REQUIREMENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- All state in a single App.jsx. No external state libraries.
- Left panel search filters the visible ticket list by ID or description.
- Ticket list merges SAMPLE_TICKETS with runtime tickets 
  (runtime wins on duplicate IDs) via a Map.
- Ticket cards already processed do not re-animate on re-selection.
- getPipelineState(ticketId) helper: reads ticket.comments to derive 
  enrichment / sopMatch / historicalMatch / escalation / isDuplicateOf 
  / kbArticlesOnly booleans/objects.
- All animations must clean up with clearTimeout on unmount/re-render 
  (return cleanup from useEffect).
- Use only lucide-react icons: Cpu, Database, BookOpen, Wrench, Search,
  Inbox, ArrowUpRight, CheckCircle, Copy2, Play, Zap, Bot, User.
- No placeholder <img> for user avatars — use initials in a colored 
  rounded div instead.
- Responsive: the 3-panel layout requires min-w-0 on the center panel 
  so it doesn't overflow.
- Do NOT add any backend, auth, or real API calls.
